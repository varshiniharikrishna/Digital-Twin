# Reviewer checklist: implementation and evidence status

This checklist records what is implemented and what the current project cannot substantiate. The evaluation used the user's locally modified Desktop CSVs as read-only inputs; their provenance was not independently verified. The project generator creates synthetic data, and these results must not be treated as clinical validation. Metric fixes removed post-baseline week-1 predictors, stopped imputing missing targets from predictors/estimates, excluded labels estimated not to be available by each cutoff, used actual enrollment dates to exclude three mislabeled 2026 rows, and replaced shuffled K-fold CV with expanding temporal windows. Because the source has no outcome-recorded date, label maturity is estimated from enrollment plus observed duration.

| 1 | Validate on real, de-identified patient records | **Not completed.** No approved clinical dataset or partner access is present. The README identifies OAI (limited to knee OA) and a clinic/registry partnership; KneE-PAD supports exercise-sensor research, not longitudinal recovery validation. |

Duration holdout R² = 0.752. These remain unverified-provenance proxy-data metrics, not clinical performance. ## Reproduce the evaluation

From the project root, run `DT_DATA_SOURCE=csv python3 research_evaluation.py`. To use a chosen CSV directory, set `DT_CSV_DIR=/absolute/path/to/csvs`; that directory takes precedence over bundled `output/`. The script writes `output/research_evaluation.json` and does not modify input CSVs. Verify data provenance before citing any metric.
