This is a traceability note for the patent-review checklist. It distinguishes code/documentation from claims that require real clinical evidence. The checked-in `output/*.csv` dataset is synthetic; the local CSV snapshot used by reports is treated as **unverified provenance** and must not be described as clinical data. No approved real patient dataset or clinical partner export was supplied.

## Reports and reproducibility

The checked-in `reports/` artifacts identify their data source. `reports/research_evaluation/research_evaluation.json` and similarity/deviation outputs are synthetic/unverified-provenance demonstrations. The full `run_all.py --skip-benchmark` attempt was interrupted during the deviation refit because the ensemble was still training; it did not produce a new complete `reports/SUMMARY.md`. Run the analysis in a normal local Python environment with sufficient time. Do not cite partial/stale reports as a completed run.

With authorized data, follow `docs/DATA_REQUIREMENTS.md`, then run `python3 validate_real_data.py /path/to/approved_export.csv`. For public data exploration, see that guide: OAI offers longitudinal knee osteoarthritis clinical/PROM data with account/use conditions, while KneE-PAD is useful for wearable exercise assessment but not final recovery prediction. Neither should be treated as an automatically suitable or directly schema-compatible dataset.
